# Your run: shell (the real Tauri window, read from its code)

Your name is `shell`. No tester has ever driven the real Tauri window (sweeps.md "Ground not yet covered" 1); you can't either, so read it and prove the faulty logic headlessly or with `cargo check`-free reasoning plus small scripts. Hunt in this order.

1. **`apps/desktop/src-tauri/src/main.rs`** (774 lines) and `tauri.conf.json`: how it spawns `ore` (arguments, quoting, a library path with spaces or unicode, stdin/stdout sizes, a command that hangs, a child left running when the window closes), file-system and shell scopes (can the page reach files or run commands it should not?), the global quick-quiz shortcut and menu bar item, the second window, ⌘Q and window close while writes are out (drafts, a note mid-save, a review rating), open at login, deep links / file opens from Finder.
2. **The page side of those seams**: `apps/desktop/src/ore.ts` (how a command is run, timed out, retried, queued; `whileOut`), `native-menu.ts`, `menubar.ts`, `quick.ts`, `QuickQuiz.tsx`, `media-keys.ts`, `now-playing.ts`. Menu items whose enabled state or action disagrees with the screen; a menu shortcut that also fires the page's own key handler (double action); the quick quiz and the main window rating the same exercise.
3. **Auto-update and install** (`apps/desktop/scripts/auto-update.ts`, `compile-cli.ts`, `bundle-cli.ts`, `.githooks/`, `package.json` scripts `app:install`): a pull that lands mid-write, a reinstall while Ore is open or frontmost, a failed build leaving no app, the bundled `ore` disagreeing with the app's version, two updates at once, the iPhone rebuild step.
4. **Release CSP** (`tauri.conf.json` CSP vs what the code loads: fonts, images from a source's folder via `convertFileSrc`, YouTube embeds, data/blob URLs, workers). `bun run release:check` only visits five screens: find a screen or source type whose loads the CSP would refuse.
