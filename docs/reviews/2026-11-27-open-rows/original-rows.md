# Group `original`: a saved web page's own files

- **F684** A saved HTML page kept as an original can't show a figure it loads from its own folder (Codex deep scan 5, original-06; its red script is `docs/reviews/2026-11-25-codex-deep-scan-5/red/original/original-assets.ts`, its skip note in `FIX-NOTES-original.md`). **Tyler's pick (2026-11-27): an offline viewing copy.** The kept original stays byte for byte as it is (D122, original-03). On add (and reimport) of a saved HTML page, Ore also writes a derived viewing copy inside the source's own folder, whose references to the page's own files point at copies of those files kept beside it (never outside the source folder, never over Ore's own names: source, thumbnail, assets; a `../` or absolute reference that leaves the page's folder is left as is). Open original shows that copy when it exists, the original otherwise. Older sources without a copy open as before. Test in `packages/core/test/` (the red script's case turned into a test: the figure resolves from the copy; the original's bytes unchanged; a `../` reference and a name clash are handled), and the intake grid cell if one names it.
