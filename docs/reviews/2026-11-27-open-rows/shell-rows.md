- **F421** A task's message goes to claude or codex as one argument; past ~1 MB (Mac) or 128 KB per argument (Linux) it fails with "argument list too long". Claude already takes a message past 64 KB on stdin (guard `long enough that it went in on stdin`). Do the same for codex (check `codex exec` reads the prompt from stdin when given `-`; read its `--help` output, do not call the AI), and stop the app passing a long chat to `ore tutor` as `--earlier` (stdin or a temp file inside the library's `.ore/`, whichever the CLI's other long inputs use).
- **F660** Closing the quick quiz while a rating saves keeps the rating but stores a session receipt of zero reviews. Last pass skipped it because `apps/desktop/test/review-session.test.ts` "closed mid-save (a click away from the quick quiz)…" expects `session end S1` before the held review is released. Look for a fix that keeps that order: the receipt written at end counts the rating already pressed but still saving (a rating pressed is a review; a failed save is the only case it must not count, so if that case matters, say how you handle it). Do not edit that test; add a new one in the same file.
- **F662** An auto-update lock left with no owner (updater killed mid-run) blocks every later pass until removed by hand (`apps/desktop/scripts/auto-update.ts`, `.githooks/`). Durable fix: the lock records its owner's pid (and start time), and a pass that finds a lock whose pid is gone takes it over. Test with a fake dead pid in `apps/desktop/test/`.
