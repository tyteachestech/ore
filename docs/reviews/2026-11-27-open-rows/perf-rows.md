# Group `perf`: reads after a change, exercises by source, iPhone media, video stall

- **F294** Filing or archiving one source reads both whole source lists again (~390 ms at 1,191 sources); the read after every change (`apps/desktop/src/change.ts`) asks for both lists. Durable fix: the change says what it touched and the read after it asks only for that (or the CLI returns the changed rows and the app merges them). Test in `apps/desktop/test/` that one archive reads one list (count calls), keeping every existing change test green.
- **F727** Any change to one source's exercises reads every exercise in the library once (packages/core). Find a source's exercises without the full read: the cards already name their source, so an index by source in `.index` (disposable, rebuilt) or the source's own folder. Library files stay canonical; `.index` may be deleted at any time and must rebuild. Test in `packages/core/test/` (a spy on the full read, or a count of files read).
- **F13** iPhone: YouTube and audio sources show the transcript as plain text: the snapshot sent to the phone leaves out `.vtt` and audio, and there is no player relay page. Find the snapshot code and the phone Reader. Fix at least the transcript (the `.vtt` reaches the phone and the phone Reader shows timed text the way the Mac does, sharing `transcript.ts`). Audio and the YouTube player on the phone may be a skip with the plan, if they need a native piece. The iPhone bundles only permissive code (CLAUDE.md Licenses).
- **F2** Video: a YouTube player that stalls mid-play is not detected or shown (`apps/desktop/src/Video.tsx`, driven over postMessage). Detect it from the player's own state (buffering past a few seconds, or the time not moving while playing) in a pure function with a test; show it with the app's existing notice or failure pattern, no new UI element (`apps/desktop/CLAUDE.md`, purpose rule). If showing it needs a new design, do the detection and skip the look with a note.
