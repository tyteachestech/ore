# Your focus (`undo`): every way back, and `ore doctor`
The app's ⌘Z runs these CLI inverses, so each must put the library back exactly.
1. **Every inverse.** For each pair, snapshot the library folder (every file but `.index`), do it, undo it, and diff: `archive`/`--undo`, `pin`/`--undo`, `cut`/`--undo`/`--redo`, `page-text`/`--undo`/`--redo`, `reimport`/`--undo [--step]` (twice, three deep), `skills rm` then `restore '<json>'`, `skills archive`/`--undo`, `course archive --undo [--lessons]`, `review`/`--undo <ts>`, `chat <id> --delete` then `--set --keep-time`, `variant reject`/`restore`, `card retire`/`restore`, `tried`/`--undo`, `dig --drop`, `edit --skills` then `--cards <cards_before>`, `suggested-skill accept`/`undo`, `inbox --remove --keep`/`--restore`, `session end`/`reopen`, `annotate --status deleted` then back, `status done`/`--at`. Then the same after an unrelated write in between, and after `reindex`. A byte left different, a card's schedule or history changed, an index left out of step (compare `ore search`/`ls`/`due` to a fresh `reindex`), or an undo that silently does nothing, is a finding.
2. **`ore doctor`.** Break a scratch library in at least twelve ways, each alone on a fresh copy: a truncated `reviews.jsonl` line, a card file with bad frontmatter, an annotation whose passage text was edited away, a source folder with no `doc.md`, a skill in a source that `skills.yaml` lacks, a duplicate card id, a chat JSON cut short, a dangling `inbox` entry, a variant line for a missing card, an image link to a missing file, a `skills.yaml` with a bad `jobs:` entry, a `.index` from an older schema. Does `doctor --json` name each with its fix, does `--fix` do what it says without losing anything, and do the other commands still run on the broken library (or refuse with the next step)?
